# Editorial: `/design style editorial`

I set the page like a printed article. Strong type hierarchy, a comfortable reading measure and images that carry the story. Controls stay quiet and rectangular.

---

## Required companion reference

I follow the [style workflow](style.md) for report context, scope, implementation and verification. The command loads it alongside this guide.

---

## The design pass

- I pair a serif for headlines and body text with a sans for navigation, labels and form controls. Print-led sites use a serif text face, a serif display face and a sans for UI, so the sans never carries long reading.
- I keep the system to two or three families. A heading face can be different from the text face, but the set stays small.
- I set body text in one column at a 60 to 75 character measure, with a line height near 1.6.
- I give the headline, deck, byline and date a clear order. The first screen says what the piece is about.
- I keep corners at 0 to 4px on images, cards and buttons. Pill-shaped buttons read as product UI, not editorial, so I avoid them.
- I separate sections with 1px rules and whitespace, not floating cards or heavy shadows.
- I use one accent for links and pull quotes. Buttons are a rectangle with a 1px border or a solid ink fill, never a gradient.
- I place images at deliberate sizes. Captions add information rather than repeat the headline.
- I test long headlines, 320px width and 200% zoom. Pull quotes and captions must follow the reading order.
